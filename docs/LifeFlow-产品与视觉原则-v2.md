# LifeFlow 产品与视觉原则 v

> 本文是 Web 主线的产品基准与视觉重制定草案。
> 已确认的产品原则直接作为开发约束；美学部分在 Doctor 选择方向后定稿。

## 一、LifeFlow 是什么

LifeFlow 不是任务清单、打卡器，也不是把一天压缩成最高效率的自动化日历。

它是一个**帮助人重新进入生活的现实型时间规划工具**：

> 当一个人面对一堆真实的事、有限的时间和不稳定的状态时，LifeFlow 帮他看清今天能做什么、先做什么，以及什么暂时做不下去。

它不替用户管理人生，也不把用户变成一组完成率数据。

## 二、项目目的

### 近期期望

做出一个无需登录、打开即可使用、离线可用的 Web/PWA 产品，让用户能够：

1. 把现实中的事情放进来；
2. 给事情补充时间、地点、描述、截止时间或重复规则；
3. 得到一份可完成的今日时间线；
4. 在现实发生变化后重新排程；
5. 看懂计划为什么这样安排、为什么有些事情没有被安排；
6. 用自己的方式完成、推迟、保留或删除任务。

### 长期目的

LifeFlow 要建立的不是“更强的自律”，而是更可靠的**重新开始能力**：

- 昨天没有完成，不等于今天必须偿还；
- 今天时间不够，不等于用户失败；
- 计划变化，不等于计划失效；
- 一件事很重要，也不意味着必须牺牲睡眠和休息。

## 三、核心用户场景

### 1. 正常的一天

用户输入几件要做的事，LifeFlow 给出顺序和时间线，用户可以手动调整。

### 2. 过载的一天

事情太多或打开得太晚，LifeFlow 不展示一面更大的失败清单，而是可以切换到“只给下一件最小的事”。

### 3. 计划被现实打断

新任务加入、固定安排变化或用户手动调整后，LifeFlow 自动重排，但明确显示发生了哪些变化。

### 4. 重复发生的生活事项

每天、每周具体某几天的任务生成独立实例。完成或跳过一次，不影响下一次，也不形成连续失败记录。

### 5. 用户想离开或迁移

数据可以导出、导入和全部删除。没有账号也不应该意味着数据被锁死。

## 四、不可违背的产品原则

### 4.1 用户事实高于系统推导

手动锁定、正在进行的任务和用户明确输入的固定安排不可被自动规则静默覆盖。

### 4.2 计划必须可解释

每个排程结果都应该能回答：

- 为什么排在这里；
- 为什么没有排进去；
- 如果想排进去，需要牺牲什么；
- 哪些安排因为重排发生了变化。

### 4.3 不为填满时间线而牺牲人

吃饭、睡眠、休息和缓冲不是可随意清空的冗余空间。必要时可以提出取舍，但不能偷偷挪走。

### 4.4 不制造羞耻型指标

不记录或强调：

- streak；
- 连续失败；
- 拖延次数；
- 完成率排行榜；
- 逾期惩罚；
- “你又失败了”式反馈。

### 4.5 任务不能消失

没有估时、没有排进去、已过期、已完成或来自重复规则的任务，都应该在某个明确的库存分组中可找到。

### 4.6 默认少打扰

不强迫用户填写所有字段，不把每个选择都变成配置表，不在用户没有请求时主动催促、总结或分析情绪。

### 4.7 数据属于用户

首版无需登录，默认本地保存；网络只用于用户明确触发的可选能力。导出和删除必须可用，不能设置隐性锁定。

## 五、规则与大模型的边界

### 本地规则 Core 负责

- 时间窗口；
- deadline；
- 任务时长与拆分；
- 休息与缓冲；
- 手动锁定；
- Replan；
- 重复实例；
- 可行性与原因码。

### 大模型可以负责

- 从自然语言中整理任务草稿；
- 建议任务顺序；
- 把规则结果解释成人能看懂的话；
- 在用户要求时提供取舍建议。

### 大模型不能负责

- 直接修改用户计划；
- 直接创建、移动或删除任务；
- 绕过休息、缓冲、deadline 或锁定规则；
- 偷偷上传本地任务；
- 代替本地规则成为离线使用的前提。

最终关系：

```text
用户事实 → 本地规则排程 → AI 可选建议与解释
```

## 六、产品结构

首版不做复杂导航，围绕一个“今日空间”展开：

```text
今日
├─ 当前 / 下一步
├─ 今日时间线
├─ 未排入与原因
├─ Inbox / 等待处理
├─ 已完成
└─ 任务编辑与数据设置
```

重复任务、手动锁定、任务详情属于任务编辑的一部分，不单独膨胀成多个管理页面。

## 七、视觉重制定：共同底线

无论最终选择哪种方向，都必须满足：

- 从左上角开始编排，不使用空内容垂直居中；
- LifeFlow 是页面主标题，日期是副标题；
- 视觉重点放在当前任务和时间关系，而不是统计数字；
- 组件有明确层级，不把所有内容做成同样大的卡片；
- 颜色用于表达状态，不用于制造警报；
- 移动端优先，触控目标清楚；
- 不依赖网络字体才能保持基本可读性；


## 十、开发验收标准

之后每个功能不只验收代码，还要回答：

- 用户能否找到它；
- 它是否增加了不必要的决定；
- 空状态是否仍然有方向；
- 失败状态是否诚实但不羞辱；
- 任务是否仍然可达；
- 刷新、离线、导出后数据是否仍然存在；
- 页面是否从左上角自然开始，且时间线仍是视觉主轴。

## 十一、当前不做

- 登录和强制账号；
- 多设备云同步；
- 社交、排行榜、连续打卡；
- 情绪或人格自动推断；
- 天气、定位、外部日历双向同步；
- 让 AI 直接代替 Planner 改计划；
- 为了“功能丰富”增加没有真实使用场景的设置项。
